## Focus Queue agent contract

- Tracking is mandatory for agent work. Use the installed Codex entry point, which records a durable launch receipt before starting an agent. Once an ECC task is known, run `focus-queue-session attach <TASK-ID>`. Use the provider's real session UUID; never guess one from the newest transcript. Reuse the existing agent record and workspace when resuming.
- Missing metadata is recoverable. A task, subtask label, plan detail, model name, branch, or session UUID can be unknown temporarily. Keep the launch receipt, use a short provisional label, and continue safe work. Put ambiguous matches in the unassigned inbox. Do not invent tasks, completion evidence, or identities to fill fields. Surface tracking failures clearly; never claim an unrecorded agent is tracked.
- Before coding, confirm the assigned workspace and Git status. New coding agents use their own worktree from a committed base; reopening reuses it. Preserve source edits and disclose that a new worktree excludes uncommitted changes. Never silently stash, reset, overwrite, or share another writer's checkout. Research and orchestration can use an existing checkout without creating a worktree. An explicitly authorized existing-workspace mode must remain visible in the tracking receipt.
- After task association, read `focus-queue-session context <TASK-ID>` and the central plan at its `planPath`. If missing, create a brief goal, scope, success criteria, implementation outline, and next step. Blank criteria remain pending clarification rather than blocking unrelated safe work. Keep the plan concise, re-read before editing, and preserve concurrent changes. Ask only when a change materially expands scope or authority.
- Put decisions and rationale, configuration, detailed progress, research, evidence, and handoffs in the adjacent `agent-log.md`. Use `focus-queue-session log <TASK-ID> <AGENT-ID> "entry"` for locked appends. Keep larger artifacts beside task context and link them. Read relevant log entries on demand; exclude full logs and decision history from routine context injection.
- Briefly state your assignment, role, provider/model when known, workspace/branch, permissions, inputs, and intended outputs. Report meaningful milestones using the helper's progress/result/attention commands, and report idle or blocked before waiting. Use helper commands instead of overwriting `context.json`. Preserve user queue order, cleared subtasks, and dismissed sessions. A finished response alone does not complete an assignment.
- Before committing anything or asking the user to test, run a sanity test of the actual affected workflow plus appropriate automated tests. Record concrete results and limitations. If the workflow cannot be exercised, say exactly why and do not claim it works. Follow the repository's commit, installation, and delivery requirements. Push only when authorized.
- The lightweight orchestrator reconciles tracking, task context, plan links, status, and approved cleanup; it answers questions and maintains authorized behavior rules. Use deterministic checks first. Do not assume authority to implement application code, deploy paid agents, change priorities, close tasks, merge branches, push, or send external messages.
- Response-ready, assignment-verified, branch-merged, and workspace-cleaned are separate states. Cleanup requires verified ownership, an inactive agent, a clean checkout including untracked/ignored files, and proof of merge into the intended target. Missing evidence means retain and explain once. Use guarded app cleanup; retain branches and canonical task documents. Archive superseded documents with provenance instead of deleting history. Never force-remove a worktree.
- Focus Queue owns terminal labels after attachment. Keep the task window title equal to the ECC ticket ID and agent tabs labeled `<TASK-ID> · <Provider> · <last 6 session UUID characters>`. Do not overwrite these with `tabname` after attachment.
