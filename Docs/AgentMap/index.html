Warm gray, crisp rules, restrained teal activity. Close to a document and comfortable for long plan reviews.

02 / THE RETURN-TO-WORK FLOW

Catch up before opening a terminal.

  1. Start with the queue.

    Keep task priority, completion alerts, and the current task where they already live.

  2. Open Central plan → Map.

    See this task’s worktree, owners, and active paths. Keep the plan and task chat one click away.

  3. Scan what changed.

    “Since last visit” marks changes in place. “Needs attention” reveals blockers and stale reports with their context.

  4. Inspect, then act.

    Read the agent’s short summary, evidence, and next dependency. Explicitly open its terminal, folder, or artifact.

On narrow panels: retain the queue, give the map horizontal scrolling, and move item details below it. The live app can reuse its inspector sizing rules. Avoid forcing a third permanent side column beside the existing conversation.

Small first collector

Read registered task metadata and Git once per worktree. Refresh visible tasks about every 5 seconds, hidden ones every 30 seconds. Cache unchanged inputs and debounce path events. These are starting targets to measure.

Stable, bounded diagrams

Start with 100 visible nodes, collapse quiet directories, and retain selection through updates. Key nodes by repository + worktree + relative path; agents by provider + session. Avoid rescanning entire directory trees.

Evidence before certainty

Preserve the last good snapshot on a collector error, show its age, and expose partial sources. A living process is presence, not proof of active work. Shared files get multiple owner chips and a “Potential overlap” label.

A map should lead directly to the work.

The prototype previews these actions in the inspector. Actual app launching belongs in the later native integration.

Single-click only inspects. Keyboard users get the same Open action. Resolve native actions from registered node IDs and allowed roots, check the file exists, and avoid shell-interpolated commands. Neovim’s flags express an inspection preference, not a security boundary.

05 / IMPLEMENTATION SEQUENCE

Ship useful visibility in small pieces.

Choose a default view, visual tone, and how much detail should appear on entry. This worktree contains only proposal artifacts.

FIRST BUILD

Workspace map

Versioned snapshot, metadata + Git collector, isolated renderer, Map tab, selection details, freshness, and native file opening. No provider instrumentation required.

SECOND BUILD

Intent + handoffs

Small declaration CLI, optional provider hooks, consumed / produced edges, overlapping claims, and “since last visit” based on saved snapshots.

EXPAND

All-agent overview

Multiple repositories and sessions, unassigned agents, linked artifacts outside worktrees, fleet filters, history, and orchestrator-authored grouping rules.

Proposed acceptance checks: identify owner, location, and blocker within 10 seconds in a small usability trial; unchanged refreshes keep the layout still; collector failures show stale data; simultaneous claims survive; filenames with spaces open correctly; a 100-node view targets under 100ms for selection and no main-thread Git work.
