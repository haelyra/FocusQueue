# T3 Code agent runtime

An agent whose `runtimeMode` is `t3` runs as a T3 Code thread in its own Focus Queue checkout. Focus Queue keeps the task, plan, checkout and cleanup; T3 Code owns the conversation. The two talk over T3 Code's local MCP endpoint (`http://127.0.0.1:3773/mcp`, protocol `2026-07-28`) with an OAuth token approved at Full access. A `t3_thread_read` snapshot is the only source of agent state: events and the list poll only mark threads dirty, and every reconnect is a full resync.

## Follow the code

- [T3Connection.swift](../../Sources/FocusQueueCore/T3/T3Connection.swift), `signIn`/`connect`/`useCurrentServer`: OAuth with PKCE, Keychain token, and the status machine (`connected`, `accessTooLow`, `otherServer`, `unreachable`, ...). It must request `settings:write`: T3 Code only issues scopes that are both requested and allowed by the approved level. `readableEnvironmentId` keeps agents live but read-only below Full access.
- [T3Services.swift](../../Sources/FocusQueueCore/T3/T3Services.swift), `live`/`handle`: wires every part together and maps each connection status to starting or stopping live updates, reconciling launches, and retrying cleanup.
- [T3Runtime.swift](../../Sources/FocusQueueCore/T3/T3Runtime.swift), `launch`: saves a launch intent before calling `t3_thread_launch` and reuses its `clientRequestId` on retry, so a lost reply reconciles (`reconcileLaunches`) to exactly one thread. `finish` cleans a checkout only after T3 Code confirms the agent stopped.
- [T3Watcher.swift](../../Sources/FocusQueueCore/T3/T3Watcher.swift): three `events/stream` subscriptions plus a 5 s `t3_thread_list` poll, each supervised with backoff and a 30 s silence watchdog.
- [T3Refresher.swift](../../Sources/FocusQueueCore/T3/T3Refresher.swift) and [T3StateDeriver.swift](../../Sources/FocusQueueCore/T3/T3StateDeriver.swift): read snapshots for dirty threads and derive status, attention and unread state; never `completed`.
- [T3ToolClient.swift](../../Sources/FocusQueueCore/T3/T3ToolClient.swift) over [T3McpTransport.swift](../../Sources/FocusQueueCore/T3/T3McpTransport.swift): typed tool calls and `T3Error` mapping (definite rejection versus outcome unknown).
- [T3AgentIdentity.swift](../../Sources/FocusQueueCore/T3/T3AgentIdentity.swift): lets `focus-queue-session` find a T3 agent from `T3CODE_THREAD_ID`, because T3 Code passes no Focus Queue environment.
- [TaskCompletionCleanup.swift](../../Sources/FocusQueueCore/TaskCompletionCleanup.swift), `run(retaining:)`, and [QueueViewModel.swift](../../Sources/ECCFocusQueue/QueueViewModel.swift), `finishT3Agents`: task completion stops T3 agents first and keeps any checkout whose agent is not confirmed stopped.

## Boundaries and checks

Every reference is bound to the server's `environmentId`; a different server is `otherServer` and gets no commands. Focus Queue cannot answer T3 approvals, only questions. Unit tests (`T3*Tests`) use fakes and the captured fixtures in `Tests/Fixtures/T3/`. Before relying on a T3 Code upgrade, rerun `Scripts/t3_contract_probe.py` and the opt-in `T3LiveIntegrationTests` (`ECC_FOCUS_QUEUE_LIVE_T3_TESTS=1`). A failure mode to keep in mind: removing a checkout while its thread still runs would leave T3 Code writing into a deleted folder.
