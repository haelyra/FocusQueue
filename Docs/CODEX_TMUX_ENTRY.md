# Codex shell entry

Normal interactive `codex`, `codex resume` and `codex fork` launches can start in Focus Queue's managed tmux server. The existing usage-bar wrapper and its flags stay in use. The original alias stays in the shell configuration for recovery.

The entry preserves prompts, quoting and provider options while normalizing `--cd` to the resolved workspace. New interactive coding agents in committed Git repositories receive an isolated worktree from the selected HEAD under `<repository>/.worktrees/<task>/agents/<agent-id>`, inside the canonical repository boundary and never under Application Support. Existing recorded sibling worktrees retain their exact paths on resume. Source edits remain untouched and excluded from that snapshot. Research/orchestrator roles (`FOCUS_QUEUE_AGENT_ROLE=research` or `orchestrator`) and explicitly approved `FOCUS_QUEUE_WORKSPACE_MODE=existing` retain their directory. Non-Git and unborn repositories remain usable with an isolation warning; agents must resolve shared-writer safety before editing.

Agent launches, including `exec`, `review`, piped starts and terminal/tmux opt-outs, must persist a private launch receipt before provider execution. The entry then invokes the local deterministic placement resolver. Repository identity selects a configured project, an explicit or saved task takes precedence, and a prompt can create the next project-prefixed task. No repository match uses the reserved Other project. Noninteractive invocations keep their existing checkout and record that policy. Help, login, completion and version checks remain utility calls. A missing task objective, label, model or native session UUID leaves a provisional tracked record. An unwritable tracking or placement store prevents launch with a visible error.

Interactive entry launches route through Focus Queue's private tmux server even when the calling shell is already inside another tmux server. The attach command clears only the child `TMUX` value so it can show the managed session without changing the user's server. `FOCUS_QUEUE_RUNTIME_MODE=tmux` prevents a managed pane from nesting again, `FOCUS_QUEUE_RUNTIME_MODE=terminal` preserves the app's explicit direct-terminal setting, and `FOCUS_QUEUE_CODEX_TMUX=off` remains a shell-level opt-out. The integration installs a zsh function and invokes the existing usage wrapper through Bash; it never adds a recursive executable named `codex` to `PATH`.

## Resume and tracking

An explicit resume UUID is checked with `focus-queue-session runtime locate codex <UUID>`. A verified running conversation opens its existing managed pane, including when the caller started inside another tmux server. Task-associated resumes must match the exact task session, agent tag, server process, session creation time, pane process and TTY before attachment. A direct-terminal conversation, conflicting task ownership or uncertain process identity prevents a second launch and reports where to continue.

Resumes use deterministic tmux names and a private launch receipt protected by a file lock. The receipt compares the full server/pane/process/TTY reference against `tmux list`, which includes every pane. This prevents a second resume while process discovery is still catching up. An unconfirmed launch keeps its intent record and requires recall before another attempt. A previously restored shell remains intact.

Resume pickers and named sessions keep Codex's normal selection behavior. Their exact conversation ID becomes known to Focus Queue through provider lifecycle events or process discovery. The pre-launch duplicate guard applies to explicit UUID resumes.

The default installation uses process discovery and verified launch metadata for tracking. It leaves native hook files unchanged, so installing the shell entry does not introduce a Codex hook-review prompt.

Provisional records live under `tracking/launches`. A corresponding private placement capsule lives under `tracking/placements/<launch-uuid>.json`, and its path is passed to Codex as `FOCUS_QUEUE_AGENT_CONTEXT`. It contains the resolved project/task, workspace, tmux identity, and project/task plan pointers. The app imports the launch ID immediately and resolves the native session UUID only after the exact saved tmux reference matches a discovered provider. Working directory, process ancestry and newest-transcript guesses never bind a conversation. A reference change triggers one immediate discovery attempt; the normal bounded recovery sweep handles startup lag without hot polling. The project inbox shows incomplete receipts and their reason while task identity is pending. Closed short-lived calls can retain an unresolved receipt if discovery missed their native UUID. Explicit UUID resumes look up the recorded workspace across tasks and refuse ambiguous or missing saved workspaces instead of creating replacements.

## Task panes and usage bar

App-created agents and shell launches with an exact task assignment share `fq-task-<task-id>`. The shell entry uses `tmux start-agent` with the exact task and provisional agent identity, then immediately notifies the app again after the pane reference is saved. Focus Queue measures the attached terminal in cells, reserves tmux status rows, gives panes a minimum usable size, and places at most four panes in one tmux window. Additional agents spill into another tmux window. Attach, resize and session-change hooks reflow automatic layouts; dragging a pane border or swapping panes switches that task to manual layout so automation does not undo the user's arrangement.

When the command includes a clear prompt, the resolver creates or selects the task before tmux starts, adds the provisional agent row, and enters that task's shared session. A bare interactive `codex` with no objective uses one `fq-codex-<launch-id>` session and remains in the matched project's inbox until Focus Queue can place it without guessing.

The installed Focus Queue usage adapter owns four status rows only inside managed tmux. Its renderer resolves `#{pane_pid}` at refresh time, so the bar follows the active agent pane. No pane stores its own PID in session-global options, and one agent exiting does not remove the bar for its neighbors. Outside managed tmux the adapter delegates unchanged to the user's existing wrapper, including the older three-row WezTerm split pane. The layout calculator subtracts the reserved rows before sizing panes. WezTerm uses one stable task tab label. Focus Queue temporarily leaves pane borders unformatted and clears its extra status-left/status-right text, so the status area contains only the usage bar and native tmux window tabs. Agent labels remain available in the app's session view and internal pane metadata. tmux-resurrect and tmux-continuum are bundled for the Focus Queue server and save layouts every five minutes, including while detached. Restore recreates shells, folders and layouts only; provider conversations resume separately from their saved UUIDs in a fresh tracked pane. Restored shells are retained, not killed, because the user may have repurposed one after restore. Prompt text and pane contents are not replayed.

This enforcement covers the configured entry point and app launcher. Invoking the native executable by absolute path bypasses a shell function. Process discovery and the global agent contract cover that route on a best-effort basis; the app does not claim an operating-system-wide execution or file-write sandbox. Child-agent lifecycle hooks remain optional because enabling them requires Codex trust review.

Native lifecycle hooks are an explicit option through `--install-hooks`. This merges hooks for `SessionStart`, `UserPromptSubmit`, `Stop`, `SessionEnd`, `SubagentStart` and `SubagentStop`. Each forwards its JSON event directly to `register-event`; identity registration needs no model response. New or changed hooks trigger Codex's interactive trust-review modal before an initial prompt can run. Choose this option when ready to review and trust the definitions through `/hooks`. The integration leaves trust records, managed requirements and hook-trust bypass flags unchanged. [Official hook documentation](https://learn.chatgpt.com/docs/hooks)

When the CLI arguments identify a prompt unambiguously, the entry writes a private launch metadata record with the exact tmux reference and at most 4096 prompt characters. Discovery can use that label only after validating the current reference. Unknown options or ambiguous positional input leave the label generic. This tracking path works independently of native hook installation and trust.

## Install and recovery

The app bundle includes both installer and entry scripts under its shell resources. The installer accepts an absolute existing usage-wrapper path and explicit flags. For the current usage-bar setup, the selected flag is `--yolo`; it is preserved from the existing alias rather than introduced as a new default.

Run the installer with `--check` to preview its destinations, then run the same arguments without `--check` to install. Default installation appends one marked source block to `.zshrc` and installs the entry under the application's support directory. Adding `--install-hooks` also merges native hook definitions while retaining unrelated entries. Existing files are backed up and a failed install rolls back changes. Re-running the installer with the same settings makes no changes. A later default install retains any hook definitions already present.

App updates refresh an already configured, recognized entry script and its managed-tmux usage adapter without changing the source block, selected external wrapper, flags or native hook trust. A fresh machine still needs the shell setup above because the external usage wrapper and approved flags are user-specific.

The exact shareable global instruction payload is [CODEX_GLOBAL_INSTRUCTIONS.md](../Config/CODEX_GLOBAL_INSTRUCTIONS.md). App installation merges its marked block into the default `~/.codex/AGENTS.md`, preserving personal text outside it. Incomplete or duplicate markers stop installation for review. Backups and rollback cover the prompt; uninstall retains it and shell settings rather than deleting personal configuration. A custom `CODEX_HOME` or higher-priority override requires the same block in that installation's effective instruction file. Restart existing Codex conversations to load updated instructions.

For a coworker testing the prompt now: copy the whole marked payload into their effective global instructions once, retain their own personal sections, then start a fresh session. The prompt guides behavior; install the app/helper and shell entry to test enforced pre-launch tracking.

## Lightweight maintenance

Semantic task/agent changes trigger a deterministic, per-task leased pass; a 60-second recovery sweep catches missed changes and merges. No model runs per launch. The pass repairs missing or empty plans and logs, explains incomplete criteria, and writes changed findings to `maintenance.json` with content-addressed audit receipts. Repeated unchanged findings do not create repeated receipts. Task details expose the findings in a collapsed tracking/workspace section. Corrupt neighboring task files are skipped during discovery but remain strict blockers for destructive cleanup.

`focus-queue-session reconcile <TASK-ID>` runs the same maintenance path. Add `--no-cleanup` to repair context and save findings without changing worktree registration. Both commands write context/receipts. Completed assignments are evaluated separately from response readiness, merge and cleanup. Only fully owned, clean, merged, inactive app-managed worktrees are eligible. Cleanup verifies the repository-owned worktree root and exact filesystem identities, moves the exact checkout to a recoverable retained sibling without following symlinks, rechecks tracked, untracked and ignored content, then moves its exact Git administration directory out of Git's active worktree registry. No checkout files are recursively deleted. The branch, canonical documents, retained checkout and recovery metadata remain available. Locked worktrees, submodule metadata, partial process inspection, changed identities and incomplete cleanup are retained for review. Shell-created external worktrees retain their launch ownership receipt for review. Superseded document archival is an explicit orchestrator action, never a heuristic deletion sweep. Priority changes, task closure, merges, pushes and paid-agent launches require separate authority.

New shells load the function automatically. Existing shells can source the updated shell configuration. To return to the old alias, remove the marked Focus Queue source block and start a new shell. Backups contain the original files and a recovery manifest. Data and launch receipts remain available.
